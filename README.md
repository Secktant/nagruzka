# Нагрузка

Личный платёжный календарь: показывает будущую финансовую нагрузку по периодам
(15-е число и конец месяца), считает % нагрузки, остаток и распределение по банкам.

PWA, работает офлайн, ставится на iPhone «На экран Домой».
Прод: https://secktant.github.io/nagruzka/

## Как устроено

- **Без сборки и без рантайм-зависимостей** — vanilla JS, ES-модули, `<script type="module">`.
  Открывается как есть; в этой папке лежит корень сайта.
- `js/engine.js` — чистый движок (генерация периодов, расчёт нагрузки, рассрочки).
- `js/store.js` — состояние `S{}` + персистентность, `js/render.js` — диспетчер вьюх,
  `js/views/*` — экраны: периоды, долги, график, деньги (зарплата, регулярные, банки)
  и настройки (бэкап, keyfile, синхронизация, замок).
- `js/crypto.js` / `js/sync.js` / `js/db.js` / `js/lock.js` — шифрование, синхронизация,
  IndexedDB, замок.
- `sw.js` — service worker (network-first + офлайн-кэш). Константа `CACHE` = версия
  приложения, её видно меткой в правом нижнем углу.

## Приватность

Zero-knowledge: сервер синхронизации хранит **только шифротекст**. Ключ выводится на
устройстве через Argon2id из пароля и keyfile, данные шифруются AES-256-GCM. Локально
данные лежат зашифрованным снимком; опционально включается замок по Face/Touch ID.
В репозитории — только код, ни байта пользовательских данных.

## Разработка

```sh
npm install          # только devDependencies (Playwright для smoke-теста)
npm test             # юнит-тесты: node --test
python3 -m http.server 4323   # локальный запуск
```

CI на каждый пуш: юнит-тесты + проверка полноты `ASSETS` в `sw.js` + boot-smoke в реальном
браузере. Деплой на GitHub Pages — только после зелёного CI.

**При добавлении нового js-файла** обязательно внеси его в `ASSETS` в `sw.js`, иначе
проверка упадёт и файл не попадёт в офлайн-кэш. Версию `CACHE` поднимай при каждом деплое.

### Argon2 и SRI

`js/vendor/argon2.umd.min.js` (hash-wasm 4.12.0, UMD) задаёт `globalThis.hashwasm` для
`js/crypto.js` — это она выводит ключ из пароля. У её `<script>` в `index.html` стоит
атрибут `integrity`: браузер сверяет хеш файла и **не выполняет** его, если файл изменён.
Защита от подмены криптобиблиотеки — подменённая версия не запустится вместо того, чтобы
тихо работать скомпрометированной.

Поэтому при обновлении библиотеки хеш надо пересчитать, иначе приложение перестанет
стартовать:

```sh
openssl dgst -sha384 -binary js/vendor/argon2.umd.min.js | openssl base64 -A
```

Результат подставить в `integrity="sha384-…"`.
