# Кандидат: долги с месяца добавления

Обновлено **2026-11-25**. Ветка `fix/debt-month-candidate`, CACHE **1.12.8**.

## База и состав

- Подтверждённый релиз main — **1.12.6**, `c861f8f` (PR #14).
- Кандидат основан на `c7a1805` ветки release-checks: актуальные инструкции,
  полный регресс и workflow check/trace-probe/publish со сверкой артефакта main.
  История результатов инфраструктуры — [RELEASE-CHECKS.md](RELEASE-CHECKS.md).
- Из `551d54a` и `7ccd307` перенесено только исправление долгов и его тесты.
  Незавершённые правки основной копии app/ в кандидат не включены.

## Поведение

- P2: «Осталось после месяца» раньше включало долги, добавленные позднее месяца.
- Новые разовые и рассрочки сохраняют локальный `createdMonth` и учитываются
  с этого месяца включительно. Правки и оплата его сохраняют.
- Для старых: явное поле → событие create по типу и ID → первый месяц платежей.
  Для рассрочки запасная дата — минимум firstPeriod/плана/привязанных записей;
  без известных дат остаток сохраняется. Непригодная история пропускается.
- Восстановленный из истории месяц закрепляется при сохранении и до сокращения
  кольцевого лога. Форматы снимка, .nz, AAD и keyfile прежние.
- Изменены engine, store, формы periods/debts и регрессионные тесты.

## Приёмка

- Добавленные в июне рассрочка 60 000 и разовый 5 000 со сроками с июля:
  в мае «Осталось после» = 0, в июне = 65 000 с правильными банками.
- Перенос, редактирование, оплата, перезапуск, сокращение истории и восстановление
  .nz сохраняют месяц добавления. Без create используется первый платёж.
- Для старой реализации finance/security/QA и ревью `7ccd307` завершены;
  эти результаты не заменяют полный регресс нового кандидата по его SHA.

## Состояние выпуска

- До публикации: профильные примеры → полный QA по [QA.md](QA.md) → ревью SHA.
- Кандидат пока не публиковался. Деплой выполняет основной агент через
  `mode=publish`, затем сверяет файлы сайта с артефактом запуска.
- Для обкатки пользователь сначала сохраняет зашифрованный .nz. Основной адрес
  сохраняется за кандидатом до решения пользователя. PR/merge main — после
  «проверил, выпускай», со сверкой одобренного артефакта [DEPLOY.md](DEPLOY.md).
- Полный регресс выявил прежний P1: no-op save рассрочки скрывал unpaid 3 000
  на дате paid 2 000. Форма теперь хранит этот остаток записью с прежним ID;
  предпросмотр и сохранение используют общий черновик, запись снимка одна.
  Устойчивая browser-регрессия smoke:debt включена в CI; повторная проверка впереди.
- QA выявил P1 на реальном abort IndexedDB: tx.onerror мог отклониться null,
  а flush пропускал такую ошибку и разрешал push. db.js теперь всегда отклоняет
  Error; сценарий реального abort, запрета push и повтора добавлен в sync-smoke.
- Прежний P1 из аудита: сейф/замок при замене Sync ID; полный QA проверяет влияние.
